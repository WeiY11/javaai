🚀 项目定位
EviMind 是一个基于 RAG (检索增强生成) 架构的企业级 AI 文档分析与智能问答平台，旨在解决企业内部海量异构数据“检索难、分析慢、准确度低”的核心痛点。
💎 核心价值
通过将本地数据向量化与倒排索引结合，建立高精度的双路检索体系，有效解决传统大语言模型应用中知识过期、回答幻觉和无法查阅私有敏感文档的三大痛点。
🎯 适用场景
企业内部核心技术文档问答、法务合同合规比对分析、医院病历及医学科研辅助笔记、智能客服一站式私有知识库。

3. 核心功能实现剖析 (Core Implementations)

3.1 RRF 无监督倒数排名融合
系统通过并行请求获取向量检索（语义）和全文检索（关键字）结果。由于两者打分体系不同，采用 RRF 算法进行无监督融合。
RRF_Score = 1 / (k + rank)
// 经验参数 k = 60
融合后执行 (score - min) / (max - min) 的 Min-Max 归一化，转化为 0~1 的置信度 (Confidence)，为后续截断和证据评估提供标准标量。
3.2 Evidence Portfolio (证据投资组合) 筛选
摒弃了传统的 Top-K 机械选取，采用贪心策略和多维价值函数从后选集中构建最强上下文投资组合。
Value = 0.62 × confidence +
0.22 × coverageGain +
0.12 × diversityBonus -
0.24 × redundancyPenalty
确保注入给大模型的数据覆盖面广且低冗余，节省宝贵的 Token 开销并提高逻辑连贯性。
3.3 证据充分性门限与幻觉阻断
在将数据喂给 LLM 前，通过计算最终充分性得分来判定是否值得回答。
SufficiencyScore = 0.70 × topScore +
0.30 × topSupportAvg
若得分低于知识库设定的 evidence_threshold，系统将强行熔断，调用 `evidence-insufficient-prompt.st` 让模型礼貌拒绝，坚决防止幻觉编造事实。
3.4 智能 Overlap 文档切片算法
采用基于语义边界的滑动窗口算法。不同于简单的固定长度截断，算法在达到 chunk_size 极限时，会向前回溯寻找标点符号（如句号、换行符）作为安全切分点。 同时，将 chunk_overlap 长度的文本片段顺延到下一个切片的头部，完美解决了长难句被拦腰截断导致的向量检索失效问题。

4. 代码架构与设计模式 (Design Patterns)

策略模式 (Strategy Pattern)

在 FileExtractorService 中得到完美应用。系统根据文件后缀动态路由到 PdfFileExtractor 或 WordFileExtractor 等具体实现类，使得未来增加新文件类型无需修改主干摄入逻辑，符合开闭原则。

模板方法 (Template Method)

在 PromptTemplateManager 中使用，统一定义了从磁盘读取 `.st` 文件的流程，并对外提供变量替换的通用接口，使得复杂的提示词工程和 Java 业务代码完全解耦。

责任链模式 (Chain of Responsibility)

在 EtlPipeline (文档摄入流水线) 中体现。将文档处理拆解为 Extract → Clean → Chunk → Embed → Index 五个独立处理器，方便后续在链条中随时插入新的过滤器（如敏感词过滤、去重）。

5. 数据库设计详解 (Database Design)

pgvector: 向量存储与 IVFFlat 索引

在 document_chunk_embedding 表中，使用原生 pgvector 扩展存储 1536 维向量：

CREATE INDEX idx_chunk_embedding_ivfflat ON document_chunk_embedding USING ivfflat (embedding vector_cosine_ops) WITH (lists = 100);

使用 vector_cosine_ops 作为余弦相似度计算标准，lists=100 为百万级数据查询提供 10 倍速度提升的近邻搜索。

JSONB: 引用信息去中心化存储

在 message 消息表中，citations（溯源引用）和 tool_calls 字段采用 PostgreSQL 强大的 JSONB 类型存储：

// citations 字段数据格式 [{"documentId": 5, "fileName": "财报.pdf", "chunkIndex": 3, "score": 0.921}]

利用 JSONB 的二进制存储与 GIN 索引支持，避免了为“消息-引用”关系建立繁琐的关联表，大幅降低了历史对话拉取时的连表 JOIN 开销。

6. 安全机制体系 (Security System)

JWT 双令牌无感刷新
  • Access Token (1小时)：包含 userId，基于 HMAC-SHA256 签名，不存库，用于毫秒级鉴权。
  • Refresh Token (7天)：作为 SHA-256 Hash 持久化存储，支持通过管理端进行远程会话撤销。
  • 前端无感延续：Axios 全局响应拦截器捕获 `401 Unauthorized`，将原始请求挂起，调用 /api/v1/auth/refresh 获取新令牌替换头信息后，重发挂起请求，实现用户零感知的安全续期。
四层立体防御架构
  • L1 接入层 Nginx IP 限流与防暴刷机制。
  • L2 过滤层 Spring Security 的 OncePerRequestFilter 构建请求隔离上下文。
  • L3 业务层 知识库 `kb_member` 数据级鉴权，杜绝越权访问私密文库。
  • L4 输出层 DOMPurify 严格清洗 Markdown 渲染 HTML，防止 XSS 代码注入。

7. 部署与微服务架构 (Deployment)

多阶段 Docker 容器化编排

使用 Docker Compose 实现一键拉起后端 (JRE)、前端 (Nginx Alpine)、PG、ES、MinIO 5大组件。网络栈相互隔离，确保组件只通过内网互相通信。

# 前端多阶段构建示例 FROM node:22-alpine AS build WORKDIR /app RUN npm i && npm run build FROM nginx:alpine COPY --from=build /app/dist /usr/share/nginx/html # Nginx 配置 proxy_buffering off 适配 SSE 长链接

8. 性能优化策略 (Performance Tuning)

Java 21 虚拟线程并行化

混合检索时，将对 PG 数据库和 Elasticsearch 的 I/O 阻塞请求投入虚拟线程并发执行。使得检索总延迟由串行的 T(pg) + T(es) 直降为 max(T(pg), T(es))。

全双工流式 SSE (Server-Sent Events)

摒弃长轮询。后端使用 Flux<StreamEvent> 发射数据帧，首字响应 (TTFT) 压降至 500ms 内。在 `onComplete` 信号触发前拦截全量文本与 `citations` 进行数据库持久化异步落盘，兼顾速度与数据完整性。

三级故障降级机制

1. ES 宕机 → 平滑降级为纯向量 PG 检索。
2. Embedding API 超时 → 降级为 ES 纯全文 BM25 检索。
3. 数据库全挂 → 熔断走大模型原生回答，前端红点预警，保障业务可用性。

9. 项目亮点与创新 (Highlights & Innovations)

  • 极致的视觉与交互体验 (前端三栏布局) 前端应用了现代化的响应式三栏架构：侧边状态栏、知识库工作区与主聊天视窗。配色方案采用高级的“霓虹太空暗夜”主题，配合细微的 Hover 毛玻璃与光效过渡 (Micro-interactions)，一举打破 B 端产品的刻板印象，带给用户强烈的高科技沉浸感。
  • 厂商无锁定的多模型热切换架构 不绑定单一 AI 供应商。基于 Spring AI 抽象，实现了 DeepSeek、智谱 GLM-4、通义千问与 OpenAI 的无缝整合。业务可在界面下拉菜单中随时“热切换”底层引擎，保障了企业对算力成本与延迟的绝对自主控制。

10. 全链路业务流转图 (Business Workflows)

文档摄入 ETL 流 (Data Ingestion)
  • 1. 上传文件至 MinIO 对象存储，MySQL 生成 PENDING 记录。
  • 2. 全局异步池调度 `FileExtractor` 策略接口剥离富文本。
  • 3. `TextCleaner` 降噪并清除乱码格式。
  • 4. `DocumentChunker` 结合重叠步长切分独立语义块。
  • 5. 批量调用 Embedding API，原子化写入 PG 与 ES。
RAG 对话生成流 (QA Generation)
  • 1. 接收查询并将其 Embedding 向量化。
  • 2. 虚拟线程并发执行双路召回并计算 RRF 融合分。
  • 3. 计算 Evidence Portfolio 价值与最高得分的充分性。
  • 4. 加载 `.st` 提示词模板注入上下文与约束规则。
  • 5. 发起大模型 Stream 调用，向前端推送事件帧。
