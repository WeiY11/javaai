# 设计原则

## 1. 单一职责原则
每个类/组件应只有一个引起它变化的原因。

## 2. 开闭原则
对扩展开放，对修改关闭。通过接口和抽象类实现扩展。

## 3. 依赖倒置原则
高层模块不应依赖低层模块，两者都应依赖抽象。

## 4. 接口隔离原则
客户端不应被迫依赖它不使用的接口。

## 5. 类型安全
- 强类型对齐项目技术栈
- Java 中定义显式类型/接口，避免不安全转换
- 文档化公共接口和契约

## 6. 视觉沟通
- 对复杂架构使用图表（Mermaid/PlantUML）
- 组件关系和数据流应可视化

## 7. 正式语调
- 设计文档使用正式、精确的技术语言
- 避免模糊描述
